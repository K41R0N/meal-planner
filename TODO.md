# Meal Planner outcomes

Approved 2026-10-26: personal single-user app, no organization switcher or multi-user accounts. Offline-first card-led web/PWA now; native Android later. The original meal-planner GitHub repository remains the central source foundation.

- [x] Fetch the meal-planner foundation and Storyteller Tactics reference repositories. Preserve the original 16 recipes and 3 condiments; do not copy purchased private deck content.
- [x] Extract the 100 highest-viewed channel videos with a written recipe below the video. Use exact dated view counts, retain source URLs and creator credits, preserve ingredients and written instructions, and deliver SQLite, CSV and JSON separately.
- [x] Integrate all 100 imported recipes plus the 16 original recipes and 3 condiments without losing source IDs. Nutrition stays unknown when absent. Distinguish source-reported values, per-serving values and unspecified bases; unsupported facts must never be guessed.
- [x] Provide a mobile-first card-led recipe book inspired by the Storyteller app's layout and interaction patterns. One shared recipe detail view is reachable from the book, weekly plan, search and logging. Android remains the primary usage target.
- [x] Combine text and ingredient search, categories, tags, meal roles, meal-prep rating and calorie/protein/carbs/fat/other available macro filters. Support sort order, editable tags/categories/rating and direct user organization. Do not impose dietary judgments or old compulsory smoothie/main/soup rules.
- [x] Save an editable one-person, seven-day weekly template with configurable days/meal slots, requested distinct recipe counts and batch portions. Random selection must honor selected suitability rules, persist without rerolling on refresh, deliberately reuse prepared portions and explain when an eligible pool cannot satisfy the request. Do not assume seven-day refrigerator storage.
- [x] Let the user lock chosen recipes, replace an individual meal or entire recipe batch, edit portions and preserve unaffected parts of the week. Recalculate shopping amounts immediately after replacements or portion edits.
- [x] Build a grocery list from planned servings and recipe yields. Aggregate only compatible ingredient identities and units, group by editable aisle, retain recipe contribution evidence, show missing/ambiguous amounts for review, and support manual additions, already-have and checked-off states without inventing cup-to-gram conversions.
- [x] Log actual consumed portions separately from planned totals. Snapshot nutrition on each log; show calories/protein/carbs/fat plus other available fields, editable targets, and visibly incomplete totals when data is missing instead of treating unknown nutrition as zero.
- [x] Keep recipes, personal edits, plans, shopping check-offs, targets and logs private on the device. Support offline viewing/planning/shopping and JSON backup/import. No account, organization switcher or multi-user setup. Do not place personal data in public Git.
- [x] Provide manual recipe addition and structured JSON recipe import using the reusable source/data model, so the bank can expand to other channels and sources. Do not claim an unattended source crawler is configured.
- [ ] Define an optional self-hosted decision adapter and editable suggestion records for Ollaya/Laya or a usable Jev alternative. Core flows cannot require AI availability. AI must not invent nutrition, allergens or storage safety. Hosting/model installation is deferred until a host is selected. The optional provider/suggestion interfaces are defined; connecting inference and persisting reviewable model proposals are deferred, not claimed as deployed.
- [x] Deliver the working app in Preview, buildable source changes suitable for integration into meal-planner, and the standalone recipe export bundle. Do not publish or replace the existing deployment automatically.
- [x] Read-only integration review against these outcomes and fix confirmed defects before handoff.
- [ ] Deferred: native React Native/Expo Android client/APK, self-hosted inference deployment and multi-user support.

Evidence: 15/15 regression tests, strict TypeScript check and production build passed. The actual Preview browser rendered all 119 recipe cards with no storage warning and an active offline cache. Source/GitHub publication still requires the separately selected release action.
